## 李萨图图形绘制

### 原理


---

#### **李萨如图形（Lissajous figure）原理：**

- **X轴**：用一路输入信号的**瞬时电压**（比如通道X、CH1）
    
- **Y轴**：用另一路输入信号的**瞬时电压**（比如通道Y、CH2）
    
- **每次采样**，将采到的两路电压值作为一个点的 (x, y) 坐标，依次绘制到屏幕上，所有点连成线，就是李萨如图形。
    

---

#### **直观理解：**

- 就像你有一支笔，横坐标跟着第一个信号（比如正弦波A），纵坐标跟着第二个信号（正弦波B），这两支“手”同步移动，轨迹就形成了李萨如曲线。
    
- 如果两信号频率一样、同相，李萨如图形是**直线**。
    
- 有一定相位差，李萨如图形会变成**椭圆**。
    
- 若频率比是简单整数比（如1:2、3:2等），会出现**优美的闭合花型**。
    

---

#### **数学表达式：**

假设

- X输入电压：x(t)=Axsin⁡(ωxt+ϕx)x(t) = A_x \sin(\omega_x t + \phi_x)
    
- Y输入电压：y(t)=Aysin⁡(ωyt+ϕy)y(t) = A_y \sin(\omega_y t + \phi_y)
    

每次采样瞬时的 (x,y)(x, y) 点，连成的图像就是李萨如曲线。

---

#### **示意图举例：**

- **同频同相**：斜直线
    
- **同频90°相位差**：圆形或椭圆
    
- **频率比1:2**：8字形
    
- **频率比2:3**：蝴蝶形
    

---

#### **在单片机上实现：**

- 使用**双通道ADC同步采样**，每次得到一对(x, y)。
    
- 把这对值转换为屏幕坐标，然后点对点、线对线地批量绘制，就能看到“李萨如图像”。
    

---

#### **总结一句话：**

> **李萨如图像，就是用两路信号的瞬时电压值分别作X、Y坐标，把所有采样点连起来，形状能直接反映两信号频率、相位关系！**

---

双轨同步采样

- 李萨如图本质上就是以**x = X(t), y = Y(t)**为像素坐标，把两个信号在同一时刻的采样值投到屏幕上形成轨迹。
    
- **只有双通道同步采样，(X[n], Y[n])才能保证“同一时刻”的真实对应**，曲线才不会变形、不抖动。


### 具体ADC配置

1. **CubeMX配置时：**
    
    - **关闭** Continuous Conversion Mode（即不要连续采样）。
        
    - **选择外部触发**（比如 TIM1 TRGO）。
        
    - DMA 选 Circular。
        
    - 配置双ADC同步模式。
        
2. **程序启动时：**
    
    - 配置好 DMA、ADC、定时器参数。
        
    - 用 `HAL_ADCEx_MultiModeStart_DMA()` 启动同步采样（只需启动一次）。
        
    - **只要定时器在运行，每次产生TRGO事件，ADC就会同步采样一组（X、Y），DMA自动把数据搬到缓冲区。**
        
3. **你就只需定时/按需启动定时器**（或让定时器一直运行，定期触发），DMA会自动循环采样、搬运数据，无需反复手动启动ADC或DMA。
    
4. **后续处理：**
    
    - 可在DMA半满/满中断处理采样数据（比如做李萨如、FFT、相位差）。
        
    - 不用管ADC/DMA何时停，采集会一直自动循环进行。


### 定时器周期

为了能够采样5KHz，一个周期应该有10～20个点，将采样频率设置为100kHz


## 方波特性测量


### **THD（总谐波失真度）计算公式**

$$\boxed{ \mathrm{THD} = \frac{\sqrt{V_2^2 + V_3^2 + V_4^2 + \cdots + V_N^2}}{V_1} }$$

- 其中：
    
    - V1V_1V1​ = 基波（1次谐波，信号主频）的幅值
        
    - V2,V3,…,VNV_2, V_3, \ldots, V_NV2​,V3​,…,VN​ = 各阶谐波的幅值（通常计算到第7次谐波，N=7）
        
- **百分比表示**：
    

$$\mathrm{THD(\%)} = \mathrm{THD} \times 100\%$$


**更推荐 40 kHz、48 kHz、甚至更高**（比如 96 kHz），这样每个谐波频点FFT能分得更清楚，能有效抑制混叠。

采用40kHz采样

## 数字芯片控制

| DAC 通道            | 逻辑名 (CubeMX) | MCU 引脚  | 默认复用功能 | 典型连接建议                              |
| ----------------- | ------------ | ------- | ------ | ----------------------------------- |
| **DAC Channel 1** | `DAC_OUT1`   | **PA4** | `AF0`  | 接 **LM339** – Vref（占空比可调）           |
| **DAC Channel 2** | `DAC_OUT2`   | **PA5** | `AF0`  | 接 **74HC4046** – VCOIN（锁相中心频率/开环调谐） |

1. **DAC 参数设置**

|选项|建议值|
|---|---|
|Resolution|12-bit right-aligned|
|Trigger|**None**（软件刷新即可；如需自动刷新可选 TIM6/7）|
|Output Buffer|**Enable**（默认即可，驱动能力更强）| 
2. **生成代码后，初始化 & 启动两路通道**
    
```
/* DAC 句柄由 CubeMX 自动生成 hdac */ 
HAL_DAC_Start(&hdac, DAC_CHANNEL_1);   // PA4 -> LM339 Vref 
HAL_DAC_Start(&hdac, DAC_CHANNEL_2);   // PA5 -> 4046 VCOIN
```

4. **在运行时写入数值**
    
```
/* 12-bit 数据: 0~4095  对应 0~VDDA (≈3.3 V) */ 
uint16_t vref_code = 2048;   // 约 1.65 V，占空比 50 % HAL_DAC_SetValue(&hdac, DAC_CHANNEL_1, DAC_ALIGN_12B_R, vref_code);  uint16_t vco_code  = 3000;   // 约 2.41 V，提高 VCO 中心频率 HAL_DAC_SetValue(&hdac, DAC_CHANNEL_2, DAC_ALIGN_12B_R, vco_code);
```

### 电路连接 & 细节

- **LM339**
    
    - 把 PA4 直接接到比较器负端 (-)，正端(+) 接三角波。
        
    - 若需要更低噪声，可在 PA4 与地之间并 **10 Ω + 0.1 µF RC** 去毛刺。
        
- **74HC4046 VCOIN (脚 9)**
    
    - 将 PA5 通过 **100 Ω 电阻** 接入 VCOIN，可防止数字干扰直接耦入环路。
        
    - 若环路滤波器已包含电容，可直接并联。
        
- **电源隔离**
    
    - DAC 输出为 0 – VDDA（≈3.3 V），确认 LM339 & 4046 也工作在 3.3 V 或保证兼容输入范围。
        
    - 若 4046 用 5 V，需要在 PA5 与 VCOIN 之间加 **轨到轨运放缓冲**（如 MCP6001）或简单 RC＋二极管钳位。

## 大彩屏


### 一、核心机制

你的主循环（`while(1)`）实际上有两个主要任务：

#### 1. **实时接收并处理串口屏发来的指令**

- `size = queue_find_cmd(cmd_buffer, CMD_MAX_SIZE);`
    
    - **作用**：从接收缓冲区里读取一帧完整的指令，返回其长度（`size`）。
        
- `if (size > 0 && cmd_buffer[1] != 0x07)`
    
    - **含义**：如果收到了指令，且这不是“开机提示帧”（一般开机信息特定字节标识 0x07），就执行后续解析。
        
- `ProcessMessage((PCTRL_MSG)cmd_buffer, size);`
    
    - **作用**：对接收到的指令包进行详细解析和处理，可能包括触摸事件、画面切换等。
        
    - 其中如果解析到的是“画面切换”相关指令，还会**自动调用 NotifyScreen()**。
        

#### 2. **定时刷新 UI（避免数据刷屏导致溢出）**

- `if (time%20==0)`
    
    - **含义**：每隔 20 个循环（假设你的 time 变量为循环节拍），才调用一次 `UpdateUI()`。
        
    - 这样可以做到**定时刷新**，比如每 200 ms 刷新一次屏幕显示。
        
- `UpdateUI();`
    
    - 作用见下文。
        

---

### 二、函数解释

### 1. `NotifyScreen(uint16 screen_id)`

- **触发时机**：每当画面切换指令被解析（比如用户点按钮切换了页面）。
    
- **作用**：
    
    1. 记录当前屏幕 ID（全局变量）。
        
    2. 判断切换到哪个画面，并**只针对当前画面更新所需的控件**。
        
    3. 例如：
        
        - 画面 1：更新速度、航向角等传感器数据。
            
        - 可以对不同画面写不同的动作逻辑。
            

**示例代码片段分析**：

```c
void NotifyScreen(uint16 screen_id)
{
    current_screen_id = screen_id;
    if(screen_id == 1) {
        AnimationPlayFrame(1,9,0);    // 播放动画帧
        SetTextInt32(1,2,Left_val,0,1);  // 控件2显示左轮速度（整数）
        SetTextInt32(1,3,Right_val,0,1); // 控件3显示右轮速度
        SetTextFloat(1,4,attitude.yaw,1,1); // 控件4显示航向角（浮点）
        SetTextInt32(1,5,mag_letf_sensor,0,1); // 控件5显示左磁传感器
        SetTextInt32(1,6,mag_right_sensor,0,1); // 控件6显示右磁传感器
    }
}
```

- **SetTextInt32/SetTextFloat** 都是和串口屏通信、更新数据的函数，参数分别是【画面 ID，控件 ID，数据，...】
    

### 2. `UpdateUI()`

- **作用**：周期性刷新界面数据——通常用来做“自动刷新”，防止画面数据卡死或丢包不更新。
    
- **刷新频率**：不宜过快，10~100ms/次较合适（太快易屏内存溢出）。
    
- **实现**：本质和 NotifyScreen 类似，都是判断当前处于哪个界面，然后有选择性地推送新数据到控件。
    

---

### 三、主循环整体思路

- **第一优先级**：响应屏幕指令（如用户点击、画面跳转等事件）。
    
- **第二优先级**：定时、自动刷新各个控件的数据（防丢包、确保实时性）。
    
- **数据分离**：用 current_screen_id 管理“当前处于哪个页面”，只有切换到相关页面时才更新对应控件，节省带宽和 CPU 占用。
    

---

### 四、风格点评（适合初学者和进阶者）

- **优点**：主循环里任务分明，既能及时响应串口屏的主动“事件”，也能定时保证UI数据刷新，兼顾实时性和安全性。
    
- **需注意**：
    
    - 刷新频率不要过高，200ms 一次较合适。
        
    - 如果有 DMA 接收或队列溢出问题，注意缓冲管理。
        
    - 推荐所有**和界面相关的动作都写在 NotifyScreen 或 UpdateUI**，保持主循环的简洁。
        

---

### 五、简要流程图

```
while(1) {
    // Step 1: 检查是否有串口屏指令，处理事件（如触摸/页面切换等）
    if (收到有效指令) {
        ProcessMessage(...);
        // 如为页面切换，会自动进入 NotifyScreen();
    }
    // Step 2: 定时刷新UI（如刷新传感器数值到界面上）
    if (到刷新周期) {
        UpdateUI();
    }
}
```

---

**一句话总结：**  
这个结构实现了**串口屏“事件驱动 + 定时刷新”混合机制**，既保证了响应性，又兼顾了数据实时性和系统健壮性。你只需根据控件需求填充 SetTextInt32/SetTextFloat 这些接口即可，别忘了定期刷新和画面切换的判定逻辑是整个数据更新的核心。
