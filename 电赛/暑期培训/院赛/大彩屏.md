```c
void MX_USART3_UART_Init(void)
{
    huart3.Instance        = USART3;
    huart3.Init.BaudRate   = 115200;          // 与屏一致
    huart3.Init.WordLength = UART_WORDLENGTH_8B;
    huart3.Init.StopBits   = UART_STOPBITS_1;
    huart3.Init.Parity     = UART_PARITY_NONE;
    huart3.Init.Mode       = UART_MODE_TX_RX;
    HAL_UART_Init(&huart3);

    HAL_UART_Receive_DMA(&huart3, rxBuf, RX_LEN);
    __HAL_UART_ENABLE_IT(&huart3, UART_IT_IDLE);   // IDLE 中断分帧
}

/* 兼容例程的单字节发送接口 —— 必须叫 SendChar */
void SendChar(uint8_t t)
{
    USART3->DR = t;
    while((USART3->SR & USART_SR_TC)==0);     // 等待发送完成
}
```

## ③ 主循环参考模板

```c
uint8_t  cmd_buffer[CMD_MAX_SIZE];
uint16_t time = 0, size = 0;

while(1)
{
    size = queue_find_cmd(cmd_buffer, CMD_MAX_SIZE);   // 从 DMA/FIFO 取一帧
    if(size > 0 && cmd_buffer[1] != 0x07)              // 0x07 = 开机提示帧
    {
        ProcessMessage((PCTRL_MSG)cmd_buffer, size);   // 内含 NotifyScreen()
    }

    if(time % 20 == 0)   // 200 ms 一次（假设 SysTick 10 ms）
    {
        UpdateUI();      // 定时刷新文本、动画等
    }
}
```

### NotifyScreen / UpdateUI 的写法

```c
void NotifyScreen(uint16_t screen_id)

    }

void UpdateUI(void)
{
    if(current_screen_id == 1)   // 仍在画面 1
    {

        // …同上
    }

```

> **别把 UpdateUI() 设太快**；厂家建议 10-100 ms 写一次，200 ms 更保险，避免屏端缓冲溢出。

## ⑤ 常见坑排雷

|症状|快速定位|
|---|---|
|下载卡住 0 %|波特率对不上；确认屏侧拨码/焊点已选 **TTL**；USB-TTL 模块接线 TX↔DIN、RX↔DOUT。|
|屏上电无显示|开发板 5 V 电流不足；7 寸屏背光最亮需 0.5-0.7 A【turn11file4†L21-L25】。换独立 5 V 1 A 适配器并两根 VCC 脚。|
|偶发乱码|串口线过长或未共地；TX/RX 拖线加 10 cm 地线并行或屏蔽线。|
|MCU 死机/溢出|UpdateUI 调度过快；或 DMA 缓冲太小，触摸连续点屏导致丢帧。|

## USART配置

是的，为了可靠地接收屏端连续不断的 UART 帧，而且能在任意时间检测到“帧结束”信号（IDLE），建议把 **USART3 RX** 设成 **DMA 接收**，再配合 **IDLE 中断** 分帧。这样做的好处是：

- **不丢字节**：DMA 会硬件级地把收到的每个字节存到内存，不用你在中断里逐字拷。
    
- **自动分帧**：当一帧数据（屏端指令）发完后总线上空闲，IDLE 中断触发，你就知道这一帧收完了。
    

---

## 在 CubeMX 中的配置

1. **打开 USART3**
    
    - Mode 选 **“Asynchronous”**，勾上 **“DMA RX”**（不勾 TX DMA，TX 直接用 HAL_UART_Transmit 即可）。
        
    - BaudRate 115200、8N1、无流控。
        
2. **打开 DMA**
    
    - CubeMX 会自动帮你在 DMA Request 里把 **USART3_RX** 连到一个 DMA 流/通道。
        
    - 在 “NVIC” 选项里，勾上 **USART3 global interrupt**（用来捕捉 IDLE）。
        
3. **生成代码**
    
    - 你会在 `usart.c` 里看到类似 `HAL_UART_Receive_DMA(&huart3, rxBuf, RX_LEN);` 的调用，以及一个 `hdma_usart3_rx` 的句柄。
        

---

## 关键代码示例

```c
#define RX_LEN    256
static uint8_t rxBuf[RX_LEN];         // DMA 原始接收区

void MX_USART3_UART_Init(void)
{
    huart3.Instance          = USART3;
    huart3.Init.BaudRate     = 115200;
    huart3.Init.WordLength   = UART_WORDLENGTH_8B;
    huart3.Init.StopBits     = UART_STOPBITS_1;
    huart3.Init.Parity       = UART_PARITY_NONE;
    huart3.Init.Mode         = UART_MODE_TX_RX;
    huart3.Init.HwFlowCtl    = UART_HWCONTROL_NONE;
    HAL_UART_Init(&huart3);

    // 启动 DMA 接收
    HAL_UART_Receive_DMA(&huart3, rxBuf, RX_LEN);
    // 开 IDLE 中断，用于分帧
    __HAL_UART_ENABLE_IT(&huart3, UART_IT_IDLE);
}

void USART3_IRQHandler(void)
{
    // 先处理 IDLE
    if(__HAL_UART_GET_FLAG(&huart3, UART_FLAG_IDLE))
    {
        __HAL_UART_CLEAR_IDLEFLAG(&huart3);
        HAL_UART_DMAStop(&huart3);
        uint16_t len = RX_LEN - __HAL_DMA_GET_COUNTER(&hdma_usart3_rx);
        queue_put(rxBuf, len);               // 推到你的 FIFO
        HAL_UART_Receive_DMA(&huart3, rxBuf, RX_LEN);  // 重新开启
    }
    HAL_UART_IRQHandler(&huart3);  // 处理其它中断（如 TX 完成）
}
```

- **rxBuf** 用 `uint8_t`，长度取 256（足够放下一整帧）。
    
- **HAL_UART_Receive_DMA**：把 **USART3_RX** 与 `rxBuf` 关联。
    
- **IDLE 中断**：判断一帧结束，把 `rxBuf[0…len-1]` 推给你的 `queue_find_cmd()` 做帧解析。
    

---

这样，USART3 就能稳稳地用 DMA 把所有屏端指令收下来，再由上层队列解析、`ProcessMessage()` 分发处理。

## 大彩屏对内指令

- **Go to Page** 属于“对内指令”（Internal Command），只影响屏幕自己：
    
    - 屏幕收到以后只在自己内部修改当前页面，不会往串口发报文；
        
    - MCU 的 `ProcessMessage()`、NotifyScreen()、NotifyButton() 都不会被触发。
        
- **好处**：UI 跳页完全交给屏幕，MCU 只管后台数据采集、处理和更新画面控件，无需额外代码。
    

---

### 什么时候 MCU 端还要关注页面切换

如果你的应用里需要 MCU 知道屏幕切换到了哪个页面（比如切到某页才开始采集／上报数据），只需在 VisualTFT：

1. 在“协议与变量设置”里**勾选**“开启页面切换通知”（Enable Page Change Event）；
    
2. 在 `ProcessMessage()` 或 `NotifyScreen(uint16_t screen_id)` 里**捕获**这一事件，做相应逻辑。
    

这样，按钮触发的切页既是“对内”切换界面，同时屏幕也会发一条 `NotifyScreen` 通知给 MCU，告诉它当前的 Page ID。

## 大彩屏对外通知


### 默认状态下按键按下通知

对的，开启了“按键事件上传”之后，屏幕会在每次按钮**按下**和**弹起**时，自动发出一个 `NOTIFY_CONTROL`（`0x82`）的消息给 MCU，你就不用再去给每个按钮单独配“对外指令”了。

---

### 1. 在 VisualTFT 里如何设置

1. 打开 **工程属性** → **上传设置**（或 **协议与变量设置**）
    
2. 找到 **“控件事件通知”** / **“按键事件上传”** 子选项
    
3. 勾选 **“按下时”** 和 **“弹起时”**（Press & Release）
    
4. 保存并重新编译下载
    

此时每当你在任意页面点击或松开一个按钮，屏幕就会发：

```
5A A5 … 0x82 … screen_id ctrl_id ctrl_msg … FF FC FF FF
```

- `cmd_type=0x82` = NOTIFY_CONTROL
    
- `screen_id` = 当前页面
    
- `ctrl_id` = 被操作的控件 ID
    
- `ctrl_msg` = 0x01（按下）或 0x00（弹起）
    

---

### 2. MCU 端如何接收

在你现有的 `ProcessMessage()` 里，已经有这样的分支：

```c
case NOTIFY_CONTROL:  // cmd_type == 0x82
    if (ctrl_msg == MSG_GET_CURRENT_SCREEN) {
        NotifyScreen(screen_id);
    } else if (control_type == kCtrlButton) {
        // ctrl_msg == 1 按下， == 0 弹起
        NotifyButton(screen_id, control_id, ctrl_msg);
    }
    break;
```

在 `NotifyButton()` 里，按照 `screen_id` 和 `control_id` 判断是哪个按钮被按下/松开，然后执行对应逻辑。

---

### 3. 优势

- **无需逐个按钮配置外部命令**，全局一次性开启后所有按钮都会上传事件。
    
- MCU 就能在 `ProcessMessage()` 捕获到 `NOTIFY_CONTROL`，及时做按键响应。
    

所以，勾上“按下和弹起时”后，你的 MCU 端就能收到所有按钮的按下/弹起事件了，无需额外在 VisualTFT 里配“对外指令”。
